# LumaRing 1.3.0 验证记录

日期：2026-09-07。macOS 26.2、Apple M4、24 GB、Swift 6.3.3。

## 本次修改

- 浅米白底、深色七圆环图标，构图遵循用户提供的菜单栏参考。实际设置页与系统文件图标均确认显示新版。
- 默认展开等待 80 ms、圆盘约 255 pt、每页 12 个 App，按住快捷键选择默认关闭。安装版设置逐项确认，登录启动保持用户原来的开启状态。
- 右键菜单仅保留设置、分隔线、退出。设置页也移除“呼出轮盘”按钮和“窗口切换已就绪”状态。
- ScreenCaptureKit 的实际结果用于权限判断，不再因 CG 预检查失败而直接阻断截图。设置中新增实际检测及明确的系统设置入口。
- 预览区分权限拒绝、最小化、无法安全匹配与其他截图错误。匹配优先使用同进程的唯一标题，允许窗口移动、缩放；重名窗口要求几何唯一匹配，避免串图。

## 录屏故障诊断与恢复

1. 系统设置中的 LumaRing 录屏开关为开启，但旧版及新版实际访问都被拒绝。
2. 退出重开、关闭再打开开关均未恢复权限。
3. 在系统设置中仅移除 LumaRing 的旧记录，重新添加 `~/Applications/LumaRing.app`，按系统提示重启后，安装版显示录屏已授权。
4. 点击安装版“检测预览权限”，ScreenCaptureKit 窗口读取成功，显示“窗口预览权限正常”。
5. 同样刷新失效的辅助功能记录，重启后安装版确认辅助功能已授权。

因此，这台机器的问题是旧构建的授权记录失效。没有修改 TCC 数据库，没有调整其他 App 的权限，没有弱化系统安全设置。

本地构建采用 ad-hoc 签名；后续更换构建仍可能需要重新添加权限。现有本地证书签名探测返回 errSecInternalComponent，未更改钥匙串保护；脚本继续支持显式传入可用的签名身份。

- 真实截图测试运行于测试进程；安装版的实际 ScreenCaptureKit 授权检测另外通过，两者没有混为一谈。
