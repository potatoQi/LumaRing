# Architecture

## Data path

`NSWorkspace notifications → ApplicationCatalog → RingController → RingView`

`hover App → WindowService serial worker → batched AX attributes → RequestGate → attached window arc`

`hover window → immediate WindowPreview + PreviewService → ScreenCaptureKit still`

`release invocation chord / mouse click → hide UI → Launch Services reopen → unminimize if needed → AXMain + AXRaise`

## Interaction

The invocation chord opens the ring; mouse input selects its targets. A left click on the menu bar icon opens Settings, while a right click opens the existing settings/update/quit menu. An optional three- or four-finger trackpad tap toggles the ring independently of held-key selection. Carbon registration handles key press/release; held mode is optional and disabled by default. The controller records whether the panel was opened by the chord, so unrelated releases cannot commit a trackpad session. App hover starts the window or tab query immediately. Pointer hover is tracked separately from asynchronous query results, so release selects the actual pointed app. Window and tab preview cards appear immediately; uncached window images arrive asynchronously. Releasing in empty space cancels.

Application pages default to 12 and accept 4–24 entries. Icon sizes adapt to density. Window arcs default to six entries per page, accept 2–8 entries for both windows and browser tabs, and initially appear when multiple eligible items are present. After a secondary close, the arc stays open even for the last remaining item. The default sort order is localized application name; order remains fixed during a selection session. Center controls prioritize window pages when expanded and otherwise page applications, including when accessibility access is unavailable.

App icons show a lower-right count badge when more than one eligible window or tab is available. Counts follow each app's content mode and the minimized-window filter; partial results carry a plus sign. AppCountService makes one serial pass over the visible page when the ring opens or the page changes. Its window and browser workers are independent of hover queries, use the same bounded readers, and never prompt for permission. Only numeric results are retained; dismissal or page changes cancel the pass and invalidate late replies. Hover results supersede older count responses. There is no periodic polling or counting while the ring is hidden.

No text input filtering, number shortcuts or arrow-key navigation remains. Accessibility actions still expose selection and paging without relying on those shortcuts.

## Geometry and rendering

The transparent backing panel uses a 480-point logical coordinate space; the default visible app disk is approximately 255 points across (520-point panel). The transparent area outside the shapes is not a surface. The disk and arc share a single **fully opaque** white/black CAShapeLayer, follow system appearance and have one combined shadow. There are no visual-effect or glass views.

The primary disk is divided into equal angular app sectors spanning radii 40–118, leaving a neutral circular center. `appIndex` and `appSectorPath` share these bounds and angles; hover fills the whole sector instead of an icon tile. Center labels and paging controls fit inside the neutral circle, and returning there immediately removes app highlighting. App dragging still has to start on an icon.

The arc inner radius exactly equals the app disk outer radius (118). The secondary arc is an annular sector with straight radial sides. Hit testing and arc content clipping share this path. The background uses one continuous exterior contour spanning the disk and sector, eliminating internal seams and pill-shaped end caps, including wraparound directions. Hover keeps an open arc while traversing the selected direction; leaving schedules a cancellable 200 ms collapse.

WindowPreview owns a separate non-activating, mouse-transparent NSPanel with a default preferred size of 840 × 630 points, adjustable from 400 × 300 to 960 × 720 points. PreviewPlacement evaluates available regions on each side, keeps the largest feasible proportional size, then chooses the closest placement. It includes negative display origins and a readable fallback for exceptionally small screens. It never moves the user's window. Images maintain aspect ratio and are sampled for the card’s actual dimensions and screen backing scale, capped at 1920 × 1440 pixels. The preview panel does not take the ring's key status and does not embed the preview in the disk center.

A native 90 ms panel fade respects the system Reduce Motion setting. There is no custom animation preference, frame timer or display link. AppKit redraws only changed content. Material blur and continuous screenshots are absent.

## Ownership and cancellation

One application delegate owns one catalog, hotkey and controller, and connects the shared trackpad service. Panel instances are reused. Outside-click monitors exist only while visible. Sleep/session/display changes dismiss the UI. Closing clears app/window snapshots and image references.

Window queries run on one serial queue with lock-backed cancellation. They have a 180 ms list timeout, 120 ms per-window batch timeout, 1.2-second iteration budget and 128-window cap. Partial responses are marked. Cache lifetime is one second for up to 24 applications and is cleared on dismissal. Both the controller generation and selected PID reject stale results.

PreviewService allows one capture in flight and one latest pending request. Cancelled in-flight system work can finish, but its generation cannot update UI. Matching first requires the same process and normal window layer. A unique exact title survives a stale AX position/size; duplicate titles require unique geometry. Ambiguous matches are rejected. Legacy CG preflight does not block ScreenCaptureKit requests; actual API results update permission state, and denials are distinguished from minimized, unmatched and other capture failures. A denial suppresses repeat requests until the ring is reopened. NSCache has an 8 MiB advisory budget and 12-entry count limit. Dismissal empties it; framework allocations can be released later by macOS.

## Three-finger pinch

An independent, off-by-default setting enables inward pinch to minimize the foreground window while the ring is closed. The same process-wide trackpad listener serves both gestures and stops when both settings are disabled. `PinchRecognizer.c` uses fixed-size per-device state and emits only begin/cancel/completion callbacks: three stable contact IDs, overall contraction with at least two shrinking pairs and two fingers moving inward beyond the tap tolerance, centroid travel bounded relative to measured contraction, bounded assembly/duration/release, all-up rearming and cooldown. Swipes, extra/replaced fingers, outward motion and missing frames cancel the candidate. Qualification includes the first break-touch frame and requires at least 12% overall contraction, two inward-moving fingers and two shrinking pairs, with a 60 ms minimum duration. Hover states 6/7 never supply contraction. Once the first lift confirms a pinch, geometry is frozen while the same fingers lift within 220 ms; new/returning contacts, invalid input and frame gaps still cancel.

`PinchMinimizer` captures the focused AX window when three contacts assemble and commits after release. It resolves the foreground PID through NSWorkspace, queries that application’s AXFocusedWindow directly, and checks foreground ownership again after the read. It does not depend on the system-wide AXFocusedApplication query, which can fail even when the target app provides a usable focused window. Accessibility queries and the targeted `AXMinimized` write use a serial worker with bounded message timeouts. Application activation, disable, suspension and target expiry cancel pending work. Before writing, it rechecks the focused application/window identity and skips nonstandard, fullscreen, already-minimized or non-settable windows. No app activation, keyboard events or periodic window polling are used.

## Preferences and upgrade

Options implements tolerant decoding so newly added keys cannot reset a user's shortcut, exclusions or chosen size. A one-time v4 migration applies the 520-point logical panel (approximately 255-point disk), 12 applications per page and disabled held mode. Shortcut, exclusions, sorting and preview preferences remain intact. Deleted settings, including the former hover delay, are ignored on decode and no longer encoded. Login items remain managed independently by SMAppService.

The app uses a versioned icon resource and explicitly loads its own applicationIconImage. Installation replaces a verified whole bundle instead of merging stale contents. LaunchServices registration can be refreshed for this bundle without flushing global caches or restarting Finder.

## Trust boundaries

Window switching, previews and browser integration use public APIs. The optional trackpad tap and three-finger pinch dynamically load the system private MultitouchSupport framework, whose ABI may change with macOS; missing symbols or devices leave keyboard and mouse activation available. The window and tab paths have no network access. Sparkle is the sole third-party runtime dependency and fetches the configured GitHub update feed and user-selected archives over HTTPS. No private window-server symbols or TCC database editing. Permissions are requested through system UI. Window titles are displayed, not logged; performance logs contain durations only. Captured content stays in memory during normal use.

## Application activation

Both application selection and window selection use ApplicationActivator. It asks Launch Services to reopen the existing application with activation enabled, without creating a new process or adding Recent Items. For explicit window selection, AX unminimize/main/raise follows activation on the bounded serial worker. An app with exactly one known eligible window can fall back to application activation when its custom window does not implement AXRaise. Multiwindow selection continues to require successful target-window raising. Activation errors reach the existing error UI.

The invocation chord defaults to Option + Tab. A one-time migration updates the former Control + Option + Space default while retaining custom choices. Preview width is independently Codable, bounded on decode, and defaults to 840 points.


## Browser adapters

`Options.appContentModes[bundleID] → WindowService OR BrowserTabService → shared attached arc`

Only the stable Edge and Chrome bundle IDs are enabled. Unknown adapters and future mode values fall back to windows; each application's mode persists independently of visibility. Default preview width is 840; a one-time v6 migration replaces the previous 640 default while retaining other customized sizes.

BrowserEvents sends structured NSAppleEventDescriptor objects to an already-running PID. It uses no script strings, JavaScript, subprocesses, browser extensions, URL navigation or background screenshots. The `all` selector uses `typeAbsoluteOrdinal` (not an enum), required by Chromium's Cocoa scripting bridge. Bulk ID/title/URL reads are checked against a second ID snapshot and the window ID. Activation and closing resolve IDs within the captured source window first, querying other windows only if the tab has moved or the source window disappeared. These action paths do not read titles or URLs. Windows are addressed by unique ID throughout, and activation verifies the current tab index before writing it and the active tab afterward. Only a missing-object error permits relocation lookup; permission failures and timeouts stop the operation. It restores a minimized window, raises its browser window index, then activates the existing application through Launch Services.

A serial worker has bounded Apple Event waits (at most 700 ms each), a 2-second read / 3-second activation budget and cancellation before each event. The displayed snapshot is capped at 512 tabs across 32 browser windows. Hover queries target the selected app; a separate count worker queries visible-page apps once for badges. Browser badges use native `core/cnte` per stable window ID and request minimized state only when needed, with no tab metadata or tab-ID reads. The count path retains the same 32-window / 512-tab cap and minimized filter as the displayed list. Browser replies are bulk metadata; the cap limits retained/displayed records, not the browser's bulk response size. Closing the ring cancels reads and drops references. Permission prompts use a separate queue so they never block the UI or ordinary window reads. Hover and count queries check permission without prompting; only the explicit connect button can request automation access. Settings refresh permission state on activation, with no timer.

The bundle declares NSAppleEventsUsageDescription and the hardened runtime automation entitlement. Browser titles and URLs stay in memory and are never included in diagnostic logs. Tab hover cards display metadata, and never capture an unrelated active page as the selected background tab.


## Owner-controlled releases and updates

VERSION is the sole release version source; build-time stamping writes both bundle version fields without modifying tracked metadata.

UpdateService retains one SPUStandardUpdaterController, starts it once after launch, and observes canCheckForUpdates, automaticallyChecksForUpdates and lastUpdateCheckDate through KVO/Combine. Sparkle owns daily scheduling and persistent user choices. No custom polling timer or updater installer is implemented. Automatic installation and system profiling are disabled. Update archives are verified before extraction; the appcast and embedded notes require signatures.

The updater has menu and settings entry points. The public key and repository are committed in Resources/UpdateConfig.json. The matching private key is in the login Keychain under account local.lumaring.app and is never included in an app or source archive.

Release preparation is local: build a universal bundle with the stable Keychain signing identity selected by Resources/SigningIdentity.json, package it as a drag-to-install DMG for first-time users and a ZIP for Sparkle, sign the ZIP and appcast using the existing Sparkle key in the login Keychain, verify against the committed public key, then atomically expose four release assets (DMG, ZIP, appcast and checksums). SigningIdentity.json contains only the public certificate name and fingerprint; the private key stays in the Keychain. A missing identity stops the build; disposable CI builds explicitly request ad-hoc signing. The DMG is added after appcast generation so the update feed always selects the ZIP. Read-only mounting verifies the Applications link, app signature and exact bundle contents against the ZIP before unmounting. Failed attempts clean staging files and completed release folders cannot be overwritten. No Apple credentials or GitHub Secrets are required. CI only tests and builds; tagging, uploading and publishing remain separate owner actions. Developer ID signing is optional; unsigned-by-Apple distribution can encounter Gatekeeper and permission prompts.

## Optional trackpad tap

`MultitouchSupport contact callback → per-device C recognizer → one main-queue toggle`

`Options.trackpadTap` selects Off, Three-finger tap or Four-finger tap. New settings default to Off; legacy `fourFingerTap: true` migrates to Four-finger tap. Changing the selection restarts recognizers and invalidates queued gestures. Listening stops only when both tap and pinch are disabled. Three-finger mode displays guidance for disabling the system three-finger Look Up gesture or assigning it to Force Click. LumaRing does not modify system settings or suppress their gestures.

The contact ABI declarations are adapted from OpenMultitouchSupport under MIT; its runtime, event objects, async stream and date formatting are not included. TrackpadInput dynamically resolves only the system functions it uses. Up to 16 system multitouch devices have independent fixed-size recognizer state. Contact frames use stack storage, bounded loops and one mutex; no per-frame heap allocation, logging, timer, UI dispatch or touch history is retained. Only a completed tap schedules a main-thread action. A generation check rejects that action if the listener was stopped, restarted or suspended in the meantime.

A four-finger tap needs four distinct contacts assembled within 90 ms, at least 20 ms of full overlap and a total duration of 30–300 ms; each contact may move at most 0.025 in normalized pad coordinates and all must lift within 100 ms of the first release. Three-finger taps allow 150 ms assembly, 12 ms overlap, 30–420 ms duration, 0.035 movement and 160 ms release. Pinches require two fingers to move inward by at least 0.04, keeping them outside the tap envelope. Extra/replaced fingers, swipes, long holds, invalid coordinates and discontinuous timestamps cancel the gesture until the pad is clear. A 350 ms cooldown prevents repeated delivery. Trackpad invocation also ignores mouse events timestamped within the first 220 ms of presentation, preventing release-generated clicks from opening Settings, choosing an app or dismissing the ring. Keyboard invocation retains immediate mouse input. A fresh listener first waits for an all-fingers-up frame, so contacts already present at enable/wake cannot trigger it. This can consume the first touch after enabling if the device does not deliver an initial empty frame.

Sleep, display sleep, screen lock and inactive-session reasons are tracked separately; listening resumes only after all reasons clear. IOKit matching/termination notifications trigger a single debounced device reconnect, without periodic device polling. Unsupported hardware has a settings message and retry action. Recognition thresholds and sleep/Bluetooth recovery require physical testing on the target devices; automated frame replay does not establish real-world gesture accuracy or overall power use.

## Closing windows, tabs and apps

`RingView` captures a target on mouse-down and commits on mouse-up. Secondary items have separate close-button hit regions, checked before switching; a release on a different item cancels. Application drags must start over the icon, travel at least 6 geometry points, and end more than 18 points beyond the main disk edge to request quit. Moving back inside or pressing Escape cancels. The secondary arc is hidden during dragging and held-shortcut release cannot activate a pointer target. No new global input monitor or polling timer is added.

`WindowService.close` presses the exact window’s enabled AX close button on its existing serial worker. It checks the window and button process IDs and roles, with bounded IPC timeouts; it never sends Command-W or falls back to closing another window. `BrowserEvents.close` resolves the tab’s latest window, then addresses both objects by unique text ID for the `core/clos` command. Reordering between query and close cannot redirect the command to a neighbour. `RingController` keeps the ring open for secondary close requests, suppresses duplicate requests for the same item, and removes an item after the app accepts the request. A fresh query reconciles the actual state, with at most two delayed retries if AX still exposes the closing window. Rejected/save-cancelled closes remain or return in the list. Page indices and counts refresh, and the final single item stays in the secondary arc for sequential closing. Presentation and query tickets prevent late completions from changing a different session or selected app. Closing never activates, raises, reopens or unminimizes the target. Tab closing does not change the active tab or window index. Normal quit also avoids activating the target. Save/confirmation dialogs remain under the target application’s control.

Dragging an app out dismisses the panel before cleanup and sends normal `NSRunningApplication.terminate()` through `ApplicationQuitter` on a concurrent worker queue, after checking the captured PID and bundle ID. The drop avoids restoring/rebuilding the secondary arc before dismissal. Requests for the same target are coalesced while delivery is in progress, and a slow request does not block the main thread or another app’s request. This is a quit request, not confirmation that the app exited. Application save/cancel prompts remain under application control; no forced termination or automatic response is used.


## App menus and Option quick launch

Right-clicking a primary application opens a native context menu. `AppContextMenu` always offers Quit App; New Window stays hidden until an available command is found, with no disabled placeholder or orphan separator. A checked Windows/Tabs submenu appears only for supported adapters. App Management likewise shows a mode picker only for those adapters; other apps show a Windows label. Browser connection and Automation authorization remain required for tab operations; the standalone Open Automation Settings button is omitted. Mode changes persist in the existing per-app preferences and reload the selected application's content. Menu tracking pauses hover and suppresses dismissal caused by menu windows; empty-space right-click keeps the settings entry point.

`ApplicationWindowCreator` offers Chrome/Edge New Window immediately and, when browser Automation is already authorized, sends Chromium's native `core/crel` command for a normal `cwin`. An uncertain create result is never retried using a second mechanism. Without browser authorization it uses the AX menu route after the context menu closes and the user-selected target activates. Other apps still discover enabled commands through a bounded breadth-first AX menu search, supporting recognized English/Chinese titles and Terminal's explicit Command-N profile. Recent Items submenus cannot monopolize the search. Each visited node uses one bulk attribute read; unsupported bulk access falls back to individual reads, while a timed-out or destroyed node is skipped. The discovered menu item is retained for that context menu only. Execution revalidates its owner, role, title and enabled state, avoiding another tree traversal when it is still valid. Invalidated items trigger fresh discovery, but a failed press is never retried. Every execution revalidates the PID and bundle identifier; no guessed shortcut or new permission prompt is used. Quit reuses the existing asynchronous normal-quit service.

`Options.launcherApps` stores an ordered, deduplicated list of app bundle IDs, names and locations. The App Management settings page adds installed application bundles and removes entries. `LauncherCatalog` resolves matching bundles, falls back to Launch Services when an app moved, and caches configured icons. `ApplicationLauncher` uses normal Launch Services opening, without forcing another process instance. Missing apps remain visible but disabled.

A fresh Option press while the panel is open, with no secondary arc, pointer gesture or context menu active, enters quick launch. Option held during invocation must be released first. Entering cancels pending window/preview work and clears primary selection; late results cannot replace the launcher. The primary disk is dimmed and disabled, including its accessibility actions. The outer circle displays 12 configured apps per page, with scrolling and central page controls. Mouse-down/up must target the same app while Option stays held. Releasing Option or pressing Escape cancels any pending launcher click and restores the primary ring. All modifier handling is local to the visible panel; no global listener or background polling is added.


A center double-click toggles a pinned Quick Launch ring that stays open after Option is released. Stationary consecutive center double-clicks accept each even AppKit click count (2, 4, 6, …), so opening and closing Quick Launch does not require pointer movement between pairs.

## Secondary names and context menus

Windows and tabs are sorted by their displayed names using localized natural comparison; exact record IDs break ties independently of the source order. A secondary item's right-click menu offers Close and Edit. Close uses the same stable target and background operation as its existing × button. Edit opens an independently retained floating panel after context-menu tracking ends, suspends pointer/modifier selection, and invalidates pending window/preview queries. Pointer exit, selection clearing and late window queries cannot discard the editing snapshot. The panel is explicitly allowed by the ring’s local click monitor. Saving uses the captured process identity and record instead of depending on hover state. Dismissal invalidates the editor callback so it cannot affect a later invocation.

`WindowRecord.title` remains the original app-provided title for capture matching and native operations. `customName` only supplies `displayTitle` for the ring, accessibility labels, preview headings and sorting. Saving a name cancels stale pointer targets, sorts again and keeps the renamed item on the visible page. Empty input restores the original title; aliases are trimmed to 120 characters.

`WindowNames` persists local aliases in UserDefaults, keyed by PID, app bundle ID, process launch time, record ID and item kind. It never matches by title or URL, so duplicate pages and changed titles do not transfer aliases. A restarted target app starts a new name scope even if IDs are reused. Complete snapshots prune names for disappeared items of that mode; limited or failed snapshots do not erase names. App lifecycle notifications prune terminated process scopes. Names and optional preset colors are local user data and are not included in the repository or release artifacts. Styles use a single name-and-color format in `windowStyles.v1`. The editor offers twelve colors in two rows and a default-color reset. A color-only style keeps the original title dynamic. Colored fills use the exact secondary sector boundaries, independent of hover.
